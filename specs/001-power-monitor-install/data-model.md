# Data Model: Power Monitor Installation

**Feature**: 001-power-monitor-install
**Date**: 2026-01-27

## Overview

This document defines the data structures and entities for power monitoring and WittyPi configuration in the vision-sensor system. Data is persisted to CSV files and systemd configuration files.

---

## Entity 1: Power Monitor Data

**Purpose**: Time-series power consumption and battery health data logged from INA219 and WittyPi sensors

**Storage**: CSV files in `/var/log/power_daily/power_YYYY-MM-DD.csv`

**Lifecycle**: Created daily at first sample, retained for 30 days, then deleted

### Schema

| Field | Type | Unit | Source | Description | Validation |
|-------|------|------|--------|-------------|------------|
| `timestamp` | ISO 8601 string | - | System clock | Sample collection time (local timezone) | Valid datetime |
| `power_watts` | Float | W | Calculated | Instantaneous power (voltage × current) | 0.1 - 10.0 |
| `supply_voltage_volts` | Float | V | WittyPi 0x03-0x04 | 5V supply voltage | 4.5 - 5.5 |
| `current_amps` | Float | A | WittyPi 0x05-0x06 | Current draw from 5V supply | 0.05 - 3.0 |
| `battery_voltage_volts` | Float | V | INA219 0x02 | Battery pack voltage | 11.0 - 14.0 |
| `battery_percent` | Float | % | Calculated | Battery state of charge | 0 - 100 |
| `ambient_temp_celsius` | Float | °C | WittyPi 0x50 | Board temperature | -40 - 85 |
| `energy_wh` | Float | Wh | Calculated | Energy consumed this interval | 0.0001 - 1.0 |
| `cumulative_wh` | Float | Wh | Accumulated | Running total for the day | 0 - 1000 |

**Sample Record**:
```csv
2026-01-27 14:23:00,1.234,5.05,0.244,12.85,45.2,22.5,0.0206,15.234
```

### Calculations

**Power (W)**:
```
power_watts = supply_voltage_volts × current_amps
```

**Energy (Wh)**:
```
interval_hours = 60 seconds / 3600 = 0.016667 hours
energy_wh = power_watts × interval_hours
```

**Battery Percentage** (4S LiFePO4 voltage curve):
```
13.6V = 100% (full)
13.2V = 80%
12.8V = 60% (nominal)
12.4V = 40%
12.0V = 20% (low)
11.6V = 10% (critical)
11.2V = 0% (cutoff)
```

Linear interpolation between breakpoints.

### Relationships

- **One-to-one with Daily Total**: Each daily CSV has corresponding `total_YYYY-MM-DD.dat` file
- **One-to-one with Daily Summary**: Each daily CSV has corresponding `summary_YYYY-MM-DD.txt` file
- **Many-to-one with Service**: All samples generated by single `power-monitor.service` instance

## Entity 2: Daily Energy Total

**Purpose**: Single-value accumulator for daily energy consumption

**Storage**: `/var/log/power_daily/total_YYYY-MM-DD.dat`

**Lifecycle**: Created with first daily sample, updated every 60 seconds, retained 30 days

### Schema

**Format**: Single floating-point value (plain text)

**Example**:
```
42.567
```

**Unit**: Watt-hours (Wh)

**Update Pattern**:
```bash
# Read current total
current_total=$(cat total_2026-01-27.dat)

# Add new energy
new_total=$(echo "$current_total + $energy_wh" | bc -l)

# Write back
echo "$new_total" > total_2026-01-27.dat
```

## Entity 3: Daily Summary Report

**Purpose**: Human-readable daily statistics for operational review

**Storage**: `/var/log/power_daily/summary_YYYY-MM-DD.txt`

**Lifecycle**: Generated at midnight for previous day, retained 30 days

### Schema

**Format**: Plain text report

**Fields**:
- Total Energy (Wh and kWh)
- Average Power (W)
- Peak Power (W)
- Battery Voltage Range (min-max V)
- Sample Count
- Operational Hours

**Example**:
```
Daily Power Summary for 2026-01-27
=================================
Total Energy: 42.567 Wh (0.043 kWh)
Average Power: 1.234 W
Peak Power: 2.856 W
Battery Voltage Range: 12.4V - 13.2V
Sample Count: 1440
Operational Hours: 24.0
```

## Entity 4: WittyPi Configuration

**Purpose**: Represents I2C register state of WittyPi 4 Mini hardware

**Storage**: WittyPi hardware registers (persistent in EEPROM)

**Lifecycle**: Set once during first-boot, persists across power cycles

### Register Map

| Register | Address | Value | Meaning | Set By |
|----------|---------|-------|---------|--------|
| Auto-boot | 0x11 | 0x00 | Manual boot (button required) | Default |
| Auto-boot | 0x11 | 0x01 | Auto boot (power-on triggers boot) | First-boot service |
| Startup Time | 0x12-0x18 | Binary | Next scheduled power-on time | runScript.sh |
| Shutdown Time | 0x19-0x1F | Binary | Next scheduled shutdown time | runScript.sh |

**State Transitions**:
```
Installation → WittyPi Installed → First Boot → Auto-boot Enabled (0x11=0x01)
                                              → RTC Synced (system → RTC)
                                              → Schedule Loaded (if .wpi exists)
```

**Verification**:
```bash
# Read auto-boot register
i2c_read 0x01 0x08 0x11
# Expected: 0x01 (enabled)
```

## Entity 5: Power Schedule

**Purpose**: Defines daily power-on/power-off times for battery conservation

**Storage**: `/opt/wittypi/wittypi/schedule.wpi` (active), `/opt/wittypi/wittypi/schedules/daily_7am_to_930pm.wpi` (template)

**Lifecycle**: Installed during setup, processed by runScript.sh, persists until manually changed

### Schema

**Format**: WittyPi .wpi format (plain text, space-delimited)

```
BEGIN   YYYY-MM-DD HH:MM:SS    # Schedule start date/time
END     YYYY-MM-DD HH:MM:SS    # Schedule end date/time (far future for indefinite)
OFF     H<hours> M<minutes>    # Duration to remain powered off
ON      H<hours> M<minutes>    # Duration to remain powered on
```

**Example** (7 AM - 9:30 PM daily):
```
BEGIN   2024-11-04 21:30:00
END     2035-12-31 23:59:59
OFF     H9 M30     # 9.5 hours off (9:30 PM to 7:00 AM)
ON      H14 M30    # 14.5 hours on (7:00 AM to 9:30 PM)
```

**Time Interpretation**: Local system timezone (configured during installation)

**Processing Output**: Writes binary timestamp to WittyPi registers 0x12-0x18 (next startup), 0x19-0x1F (next shutdown)

## Entity 6: Systemd Service Definitions

**Purpose**: Service unit configuration for power monitoring and RTC synchronization

**Storage**: `/etc/systemd/system/*.service`, `/etc/systemd/system/*.timer`

**Lifecycle**: Created during installation, enabled, started, persist until uninstalled

### Service: power-monitor.service

**Type**: Long-running daemon (Type=simple)

**Key Attributes**:
- **Restart**: always (automatic recovery)
- **RestartSec**: 10 (delay between restart attempts)
- **User**: root (I2C device access)
- **WorkingDirectory**: /opt/power-monitor
- **ExecStart**: /opt/power-monitor/witty_pi_monitor.sh

**Dependencies**: After=multi-user.target wittypi.service

### Service: wittypi-firstboot.service

**Type**: One-shot (runs once, then self-removes)

**Key Attributes**:
- **Type**: oneshot
- **RemainAfterExit**: yes
- **ExecStart**: Inline bash script (sources utilities.sh, waits for NTP, sets auto-boot)
- **ConditionPathExists**: /etc/systemd/system/wittypi-firstboot.service (prevents re-run after deletion)

**Self-Removal Logic**:
```bash
# On success:
systemctl disable wittypi-firstboot.service
rm -f /etc/systemd/system/wittypi-firstboot.service
systemctl daemon-reload
```

### Service: wittypi-rtc-sync.service

**Type**: One-shot (shutdown hook)

**Key Attributes**:
- **DefaultDependencies**: no
- **Before**: shutdown.target reboot.target halt.target
- **ExecStart**: source utilities.sh && system_to_rtc

**Purpose**: Sync system time to RTC before power-off

### Timer: wittypi-rtc-sync.timer

**Type**: Systemd timer

**Key Attributes**:
- **OnCalendar**: daily (midnight)
- **Persistent**: true (run missed executions)
- **Requires**: wittypi-rtc-sync-daily.service

**Triggered Service**: wittypi-rtc-sync-daily.service (sources utilities.sh, runs system_to_rtc)

## Data Integrity and Constraints

### Validation Rules

1. **Power Data Bounds**:
   - Power: 0.1W - 10.0W (Raspberry Pi Zero 2W typical range: 0.4W - 3W)
   - Voltage: 4.5V - 5.5V (USB power spec: 5V ±10%)
   - Current: 0.05A - 3.0A (Pi Zero 2W max ~600mA, with peripherals up to 2A)
   - Battery: 11.0V - 14.0V (4S LiFePO4 pack: 3.0V-3.5V per cell)

2. **Timestamp Validity**:
   - Must be parseable as ISO 8601
   - Must be in local system timezone
   - No future timestamps (reject if > current time + 5 seconds)

3. **File Naming**:
   - CSV files: `power_YYYY-MM-DD.csv` (strict date format)
   - Total files: `total_YYYY-MM-DD.dat`
   - Summary files: `summary_YYYY-MM-DD.txt`

4. **Atomicity**:
   - CSV append operations must be atomic (single write per sample)
   - Total file updates use temp file + mv pattern for atomicity

### Error Handling

**Invalid Sensor Readings**:
- Out-of-bounds values → Skip sample, log warning, continue monitoring
- Failed I2C reads → Retry up to 3 times, then skip sample

**Disk Full**:
- CSV write failure → Log error to journal, attempt cleanup of old files
- If cleanup fails → Service continues but stops writing (alerts via journal)

**Missing Hardware**:
- WittyPi not detected → Service exits with error (systemd will restart after 10s)
- INA219 not responding → Log warning, continue with WittyPi metrics only

## Query Patterns

**Common Queries**:

1. **Current Power Consumption**:
   ```bash
   tail -n 1 /var/log/power_daily/power_$(date +%Y-%m-%d).csv | cut -d',' -f2
   ```

2. **Battery Voltage Trend**:
   ```bash
   tail -n 60 /var/log/power_daily/power_$(date +%Y-%m-%d).csv | cut -d',' -f5
   ```

3. **Daily Energy Total**:
   ```bash
   cat /var/log/power_daily/total_$(date +%Y-%m-%d).dat
   ```

4. **Weekly Energy Consumption**:
   ```bash
   for i in {0..6}; do
       date=$(date -d "$i days ago" +%Y-%m-%d)
       echo "$date: $(cat /var/log/power_daily/total_$date.dat 2>/dev/null || echo '0') Wh"
   done
   ```

5. **Service Status**:
   ```bash
   systemctl status power-monitor.service
   journalctl -u power-monitor -n 50
   ```
